> 3. 每完成一项，在提交信息中写明；修改过的上游文件按 §4(b) 要求带显著变更说明。

## D. 文档与元数据中的自我标识

- `app/assets/i18n/*.json`：界面文案中出现的 "LocalSend"（关于页、提示语等）需替换为
  本项目名称；保留"基于 LocalSend 协议"这类来源说明。
- `app/lib/pages/about/*`：关于页的官网/仓库链接、许可证展示。
- `app/pubspec.yaml` 的 `description`；`cli/Cargo.toml` 的 `description` 与启动横幅
  （`cli/src/banner.rs` 会打印版本，注意版本号需与 `app/pubspec.yaml` 保持一致）。
- `.github/` 下的工作流与模板：本项目托管在 Gitee，建议迁移或删除上游 CI 徽章引用。

## E. 明确**不要**改的部分

- `packages/core` 中协议路径 `/api/localsend/v2/...`、`PROTOCOL_VERSION_V2`：这是**互操作
  协议**，改了就无法与官方 LocalSend 及其他兼容实现通信。
- `LICENSE`、`NOTICE`、`README.upstream.md`：保留归属。
- 上游 git 历史与作者信息：不得改写。

## F. 验收方式

1. `fvm flutter analyze`、`fvm flutter test`、`cargo test --features full` 全绿；
2. 构建出的 Android 包 `applicationId` 与官方不同，安装后可与官方版共存；
3. 与官方 LocalSend 互传（发送/接收）仍然正常——协议路径未改；
4. `grep -ri "localsend" app/android app/ios app/macos app/windows app/web` 仅剩协议路径、
   方法通道（若保留）与来源说明。
