## 三、有意保留（不改，附原因）

| 项 | 原因 |
|---|---|
| 协议路径 `/api/localsend/v2|v3/...`、`PROTOCOL_VERSION_V2` | **互操作协议**，改了就无法与官方 LocalSend 及其他兼容实现互通 |
| Rust crate `localsend`、`localsend-cli`，Dart 包 `localsend_app`、`localsend_isolates`，`rust_lib_localsend_app` | 内部包/符号名，改动会波及全部 import、FRB 生成物与 CI/Docker 目标，零对外收益 |
| 代码注释与文档中的上游 issue/仓库链接（`github.com/localsend/...`）、`localsend.org`、商店链接 | 属**来源引用与归属**，删除反而违反 Apache-2.0 的归属精神 |
| `LICENSE`、`NOTICE`、`README.upstream.md`、`support/readme/README_ZH.md` | 上游原文与许可证，必须保留 |
| `app/lib/provider/persistence_provider.dart` 的 Windows **旧版迁移路径** `org.localsend\localsend_app\shared_preferences.json` | 迁移兼容路径：从上游版本迁移过来的用户设置仍能被读取 |
| `_missing_translations_*.json` 与其它语言的翻译句子 | 翻译范畴（本项目未接入 Weblate），后续可统一；不影响功能 |
| `.github/` 工作流 | 上游 CI 定义，保留以便与上游同步；本项目实际使用 `docker/` 复现同样的检查 |
| Flatpak 清单（仓库外） | `tray_helper.dart` 中的图标名已改为 `com.gitee.ynzj.juyuwanggeiwo-tray`，**发布 Flatpak 时需让清单里的图标名一致** |

## 四、验收方式

1. **静态检查**：`grep -rn "org.localsend\|LocalSend" app/{android,ios,macos,linux,windows,web}` → 只应剩上游引用链接/注释；协议路径计数不变（`api/localsend/v2|v3` 共 73 处）。
2. **构建与测试**（容器内，见 [docker/README.md](../docker/README.md)）：
   - `docker compose -f docker/compose.yaml run --rm dart-test`（分析 + 单测）
   - `docker compose -f docker/compose.yaml run --rm dart-format`（格式，含先删 `lib/gen`）
   - `docker compose -f docker/compose.yaml run --rm rust-test`（Rust 全量测试，不受本次改名影响）
   - `docker compose -f docker/compose.yaml run --rm version-check`（发布版本五处一致）
   - `docker compose -f docker/compose.yaml run --rm android-apk`（**验证 applicationId/包名/资源改动可编译**）
3. **互通性**：与官方 LocalSend 互发文件仍应成功（协议未改）。
4. **共存性**：Android 安装后 `applicationId` 与官方不同，可与官方版共存。
5. **待人工验证（本机无 Xcode/MSVC）**：iOS/macOS/Windows 的工程引用（bundle id、App Group、`.storekit` 更名、`.manifest` 更名、MSVC 源码编码）需在对应宿主上各构建一次。

## 五、后续与上游同步时注意

- 同步上游改动时，`support/scripts/apply_rename.py` 可作为标识映射的**历史记录**（对已改过的文件是幂等的空操作）。
- 图标是占位设计，替换正式图标后重跑 `support/scripts/generate_placeholder_icons.py` 即可覆盖全部平台。
- 若上游新增文件里出现新的品牌串，按本文件的"一、统一后的标识"补充映射即可。
